🛒 6. Cart Module (Core Functionality)

    🧠 Design
    - Single table: cart_items
    - Cart identified using user_id
    - One row = one product in cart

    📡 APIs Implemented

    ➕ Add to Cart
        - POST /cart/add
        - Adds product to cart

    📥 Get Cart
        - GET /cart
        - Fetches all cart items for user
        - Uses JOIN with products
        - Returns product details, item total, and overall cart total

    🔄 Update Cart
        - PUT /cart/update
        - Updates product quantity
        - If quantity = 0 → removes item

    ❌ Remove from Cart
        - DELETE /cart/remove
        - Removes specific product from cart

🧾 7. Order Module (Checkout & Order Management)

    🧠 Design
    - orders → stores order-level data (summary)
    - order_items → stores product-level data
    - One order → many order_items

    📡 APIs Implemented

    🛍️ Checkout (Cart → Order)
        - POST /order/checkout

        What it does:
            - Reads user cart (cart_items)
            - Calculates total amount
            - Creates a new order in orders
            - Inserts items into order_items
            - Updates stock_count in products
            - Clears user cart

        👉 Uses database transaction (BEGIN / COMMIT / ROLLBACK)

    📜 Get Order History
        - GET /order

        What it does:
            - Fetches all orders for logged-in user
            - Returns order summary:
                - order id
                - total amount
                - payment method
                - status
                - created_at

    🔍 Get Order Details
        - GET /order/:id

        What it does:
            - Fetches specific order with user validation
            - Fetches order items
            - Uses JOIN with products to get product details

⚡ 8. Real-Time Stock Sync (SSE + Redis)

    🧠 Design
    - SSE keeps browser tabs connected to backend in real time
    - Redis pub/sub shares stock updates across backend instances
    - PostgreSQL remains the source of truth for stock_count

    📡 What it does

    - When checkout reduces product stock in PostgreSQL
    - Backend publishes a stock update event to Redis
    - All backend instances subscribed to the Redis channel receive the message
    - Each backend instance broadcasts the update to its own connected SSE clients
    - Frontend updates stock instantly without refresh

    ✅ What this solves
    - Real-time stock changes in UI
    - Works across multiple backend instances
    - Keeps product availability in sync for all users

    🔁 Flow
        - Order placed
        - Stock updated in PostgreSQL
        - Redis publish
        - Backend instances receive event
        - SSE broadcast
        - React UI updates instantly
